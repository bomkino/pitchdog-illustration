# Contributing

Contributions are welcome when they sharpen judgment, portability, safety, or
evidence. The goal is not more rules or more pictures. It is better decisions.

## Before changing the skill

1. Name the failure the change prevents.
2. Add or update an adversarial eval.
3. Keep `SKILL.md` lean; put depth in one directly linked reference.
4. Preserve the difference between current law, approved history, identity
   evidence, agent checks, owner acceptance, and publication.
5. Run the complete validator and same-environment reproducible package round-trip.

## Illustration assets

Do not submit:

- real family or client photographs;
- private likeness sheets, prompts, paths, IDs, or metadata;
- third-party inspiration without redistributable rights;
- a named-artist imitation;
- rejected candidates presented as calibration;
- historically approved work as current authority;
- files lacking exact provenance and public distribution permission.

Every proposed reference needs a visible quality reason, status authority,
source lineage, rights basis, SHA-256, dimensions, and full-size review. Update
the reference manifest and relevant collision catalog.

## Creative changes

Do not turn examples into templates. Add a principle only when it improves
judgment across multiple cases. Prefer counterexamples and repair logic over
adjective piles.

Identity corrections outrank older art. Preserve exact bodies, faces, hair,
coats, markings, clothing, pronouns, relationships, and scale. Never normalize
someone into a generic person, breed, gender code, or beauty standard.

## Pull requests

Include:

- failure fixed;
- files changed;
- evals added or changed;
- validator output;
- package SHA-256 and round-trip result;
- any remaining unperformed visual, identity, rights, or runtime checks.

No contributor licence agreement. 0BSD requires no attribution.
